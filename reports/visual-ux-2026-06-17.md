## Findings

### P0

1. Cross-theme AA failures on action and status surfaces
   - Surfaces:
     - Overview endpoint links
     - Servers `Healthy` and `Attention` badges
     - Tool Runner primary action
     - Storage `Create` action
   - Why it matters:
     - These are small-text UI surfaces below WCAG AA in normal usage.
   - Fix direction:
     - Do not patch locally with literals.
     - Route to brand tokens and/or component variants:
       - review `--primary` / `--primary-foreground`
       - review success and warning token pairings used by `Badge` / `StatusBadge`
       - if necessary add stronger small-text-safe token pairings in the theme layer and re-audit all six themes

### P1

1. Strict brand-ui-only rule is currently violated by bespoke interactive/media UI
   - In app code:
     - `next/image` is used for asset cards
     - raw `<img>` is used in the QPS gallery
     - raw `<button>` elements are used for folder rows and gallery tiles
     - raw `<a>` links are used as standalone UI in endpoint cells
   - Why it matters:
     - These surfaces bypass the design-system composition rules and create inconsistent interaction, state, and accessibility behavior.
   - Fix direction:
     - Replace bespoke interactive/media surfaces with verified `@brand/*` components where available.
     - If no matching component exists, build a thin local wrapper that follows brand-ui authoring rules (`forwardRef`, `cn()`, spread props) and standardize on one approved surface.

2. Empty, error, and loading states are still bespoke in several places
   - Examples:
     - placeholder chart region says `Chart row goes here.`
     - assets empty state says `No assets match the current filter.`
     - storage empty state says `This folder is empty.`
     - QPS browser error state is a raw destructive-tinted `<div>`
     - QPS browser empty/gallery selection copy is plain text
   - Why it matters:
     - The audit kit explicitly expects `EmptyState`, `ErrorState`, and `LoadingState` instead of ad-hoc markup.
   - Fix direction:
     - Replace custom empty/error/loading blocks with `@brand/ui` `EmptyState`, `ErrorState`, and `LoadingState`.

3. Repeated `space-y-*` usage breaks brand spacing rules
   - Why it matters:
     - The kit explicitly standardizes on `flex`/`grid` plus `gap-*`.
   - Fix direction:
     - Convert stacked sections to `flex flex-col gap-*` or grid with `gap-*`.

4. The rendered sort indicator shows the Unicode glyph `↕`
   - Why it matters:
     - The audit anti-pattern catalog explicitly flags emoji-like Unicode glyph affordances and recommends a Lucide icon instead.
   - Fix direction:
     - Use a proper icon-driven sort affordance from the branded table surface, ideally `ChevronsUpDown` if the underlying component allows it.
   - Note:
     - This may be an upstream `@brand/data` issue rather than an app-only issue.

### P2

1. Very small informational text appears at `10px`
   - Folder badge path
   - Asset path in QPS browser
   - Fix direction:
     - Raise body-scale utility usage to at least `text-xs` or the equivalent >=12px, preferably 14px where density allows.

2. The app body uses `min-h-screen`
   - Fix direction:
     - Use `min-h-dvh` or `min-h-[100dvh]` for viewport stability.

3. The overview chart region is still a raw placeholder section
   - Fix direction:
     - Replace with a real `@brand/charts` surface such as `ChartCard` / `ChartFrame` plus a verified chart composition.
